# Contribución

## Alcance inicial

La primera etapa está enfocada en maquetar el frontend Flutter con datos sintéticos. No requiere Docker, base de datos ni backend para avanzar.

## Flujo de trabajo

1. Crear una rama con el formato feature/nombre-corto.
2. Mantener los datos de demostración libres de información clínica real.
3. Verificar la aplicación en web antes de solicitar revisión.
4. Describir en el cambio qué pantallas y estados fueron comprobados.

## Commits

Usar mensajes breves y claros, por ejemplo:

feat(frontend): crear pantalla inicial de pacientes
